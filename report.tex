\begin{abstract}
  本项目「寻迹故宫」（Tracing the Forbidden City）在故宫官方数字全景资源（\url{https://pano.dpm.org.cn/}）基础上，实现了一款 GeoGuessr 风格的 Web 定位游戏：玩家观察 360° 全景，在离线故宫平面图上点击猜测位置，系统按误差计分并展示建筑知识。针对官方坐标与本地宫图瓦片不完全一致的问题，我们采集 24 个场景锚点，采用全局及分 panorama 仿射变换校正真值；前端集成 krpano 全景浏览与 Leaflet 宫图交互，后端 Python 提供静态资源与按需下载管理。当前版本 \textbf{1.0} 支持 24 个已锚点场景、季节/建筑问答、本地资源懒加载与报告演示模式。本文介绍项目背景、系统设计、坐标标定方法、主要功能与体验评估，并讨论局限与后续工作。
  \vspace{0.5em}
  \noindent\textbf{关键词：}数字文化遗产；全景浏览；地图定位；仿射标定；教育游戏
\end{abstract}
\section{引言}
故宫博物院自 2015 年起逐步开放线上数字漫游，官方站点提供基于 krpano 的多季节 360° 全景与配套「小地图」标点。这类资源兼具文化展示与空间认知价值，但缺少面向公众的互动玩法。GeoGuessr 类游戏通过「看街景猜地图位置」训练空间推理，若迁移至故宫场景，可在娱乐中强化对中轴线、三大殿、御花园等空间结构的理解。
本项目定位为通识课课程作品：在\textbf{不依赖官方站点在线可用性}的前提下，缓存必要瓦片于本地，完成可离线演示的完整游戏闭环；同时保留锚点标定、资源管理等可扩展接口，便于后续作为专业课前端项目的迭代基础。
\section{需求与目标}
\subsection{核心玩法}
根据项目需求文档，最小可玩版本需实现：
\begin{enumerate}[nosep]
  \item 随机（或指定）抽取一个故宫 \texttt{scene}；
  \item 在 360° viewer 中观察环境；
  \item 在故宫平面图上点击猜测坐标；
  \item 计算猜测与真值距离并输出分数；
  \item 展示正确位置、建筑名称与知识点；
  \item 进入下一题。
\end{enumerate}
\subsection{扩展目标（1.0 已实现）}
\begin{itemize}[nosep]
  \item \textbf{24 景锚点题库}：覆盖前三殿、箭亭、神武门、御花园、宁寿宫花园等代表区域；
  \item \textbf{季节小问}与\textbf{建筑知识问答}，答对额外加分；
  \item \textbf{本地资源管理}：懒下载、磁盘占用统计、按容量/题数清理；
  \item \textbf{报告演示模式}（\texttt{?report=1}）：隐藏开发向 UI，便于截图与答辩；
  \item \textbf{满分反馈}：定位误差 $\le 5$（用户坐标单位）时触发 5000 分特效。
\end{itemize}

\subsection{全景与宫图}
\textbf{全景侧}：由 Pannellum 迁移至 \textbf{krpano}，直接加载与官方一致的 \texttt{.tiles} 六面体结构（\texttt{f/b/l/r/u/d}，多级 \texttt{l1/l2/l3}），按需拉取本地 jpg，避免整场景一次性下载。
\textbf{地图侧}：Leaflet 使用 \texttt{L.CRS.Simple}，瓦片路径 \texttt{leaflet/tiles/\{z\}/tile\_\{x\}\_\{y\}.png}，世界尺度约 $8192\times 8192$ 像素（\texttt{MAP\_MAX\_ZOOM=5}）。用户点击地图时，将容器坐标反投影为「用户坐标系」下的 $(x,y)$，与锚点真值比较。
\section{坐标标定与计分}
\subsection{问题背景}
官方 \texttt{coordinates.json} 为每个 scene 提供 \texttt{x\_axis/y\_axis}，官网前端将其直接作为 Leaflet 平面坐标打点，\textbf{未做全局统一仿射}。不同 \texttt{panorama\_id} 下数据的局部尺度与偏移存在差异；本地使用一张固定 offline 宫图时，若照搬 JSON 坐标，真值与视觉位置会出现系统偏差。
\subsection{锚点采集与变换模型}
我们在宫图上人工标定真值，分两类来源：
\begin{itemize}[nosep]
  \item \textbf{manual9}：早期 9 点粗标；
  \item \textbf{captured}：调试模式（\texttt{?debug=anchors}）下逐 scene 点击落库，精度更高。
\end{itemize}
合并后共 \textbf{24} 个锚点（captured 优先去重）。标定脚本 \texttt{calibrate\_map\_transform.py} / \texttt{analyze\_per\_pano\_anchors.py} 拟合：
\begin{itemize}[nosep]
  \item \textbf{全局 6 参 affine}：作为 fallback；
  \item \textbf{per-panorama affine}：样本数 $n\ge 3$ 的分区变换，显著降低前三殿、御花园等区域的像素误差。
\end{itemize}
拟合结果（user 坐标空间）：全局 RMSE 约 \textbf{39.5}；启用本区 affine 后加权 RMSE 约 \textbf{27.0}。前端 \texttt{getSceneTruthCoord} 优先级为：\texttt{click\_pixel\_xy} 仿射真值 $>$ 锚点 \texttt{user\_x/y} $>$ catalog 回退坐标。

\subsection{计分规则}
猜测点 $(g_x,g_y)$ 与真值 $(t_x,t_y)$ 的欧氏距离为 $d$。本题得分采用分段线性插值，满分 5000 分：
\begin{table}[htbp]
  \centering
  \caption{距离—得分对照（节选）}
  \label{tab:score}
  \begin{tabular}{@{}cc@{}}
    \toprule
    距离 $d$ & 得分 \\
    \midrule
    $\le 5$ & 5000 \\
    $\le 10$ & 4500 \\
    $\le 20$ & 4000 \\
    $\le 40$ & 3000 \\
    $\le 80$ & 1500 \\
    $\le 160$ & 750 \\
    \bottomrule
  \end{tabular}
\end{table}
超出 160 后按末段斜率继续衰减至 0。提交后显示猜测—真值连线；游戏模式隐藏原始误差距离，以「本题得分 / 累计分 / 平均分」呈现。季节与建筑问答各额外 +500 分。

\subsection{满分特效（5000 分）}
当 $d\le 5$ 时，除 550\,ms 分数滚动外，叠加方案 B 反馈：计分板金边脉冲、地图金色涟漪、顶部横幅「满分定位 · 5000」、轻量纸屑动画，以及 Web Audio 三音 chime。报告模式默认静音，录屏可加 \texttt{\&sound=1}。

\section{部署与运行}
本地启动：
\begin{lstlisting}
start_server.bat    # Windows
./start_server.sh   # macOS / Linux
\end{lstlisting}
浏览器访问 \url{http://127.0.0.1:8000/}。报告演示：\url{http://127.0.0.1:8000/?report=1}。
交付方案：（A）教师机 Python + 本地瓦片子集；（B）Electron 单文件打包（约 180--220\,MB，计划中）；（C）PDF 报告 + 演示录屏。
\section{测试与体验}
\subsection{功能测试}
\begin{itemize}[nosep]
  \item 24 个 catalog 场景在本地瓦片齐全时可正常加载全景与宫图；
  \item 提交后真值标记、连线、计分与问答流程完整；
  \item 随机 / 下一题不会进入未下载场景；
  \item 锚点验证模式下真值点与 captured 记录一致。
\end{itemize}
\subsection{标定精度}
在 per-pano affine 启用后，多数 captured 锚点在本区模型下残差 $<10$ user 单位；少数 manual9 早期粗标（如太极殿、古华轩）残差仍 $>50$，已列入复核清单。对游戏而言，$d\le 5$ 的满分区间在视觉上要求点击非常接近真值，符合「精准定位」难度设计。
\subsection{性能}
早期版本在每次页面加载时扫描 \texttt{data/raw} 统计占用，导致约 5\,s 延迟；现改为打开设置面板时按需刷新并缓存 120\,s，首屏加载恢复至秒级。
\section{总结与展望}
\subsection{工作总结}
本项目完成了从官方数字全景到可玩定位游戏的迁移：集成 krpano 与 Leaflet，建立 24 点锚点与分 panorama 仿射标定 pipeline，实现计分、问答、资源管理与报告演示模式，版本 \textbf{1.0} 可用于课程答辩与交付。
\subsection{局限}
\begin{itemize}[nosep]
  \item 官方坐标与本地宫图仍存在分区系统误差，依赖持续锚点采集；
  \item 前端为 Vanilla JS 而非需求文档初拟的 React，便于快速迭代但组件化不足；
  \item 24 景全量瓦片体积约 172\,MB，教师机交付已可整体打包；如需扩展更多场景，懒下载机制可按需获取。
  \item 季节题在题库夏季占比较高，季节问答出现概率已做平衡但仍偏随机。
\end{itemize}
\subsection{后续工作}
\begin{enumerate}[nosep]
  \item Electron 打包与默认 10 景离线包；
  \item 复核 manual9 离群锚点，扩大 captured 覆盖；
  \item 倒计时、排行榜、多难度模式（猜区域 / 猜建筑）；
  \item 若迁移专业课：React 重构、TypeScript 类型与单元测试。
\end{enumerate}
